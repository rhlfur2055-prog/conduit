# 명세: 검증된 읽기 기억 (Verified Reading Memory)

- 기능 브랜치: `feat/agent-loop`
- 상태: 구현 완료 (2026-09-23) — LLM 이 필요한 부분(연결 질문의 실제 품질)은 API 키가 없어 미측정
- 입력 요청: "openclaw 처럼 글자를 읽으면 문맥 파악이 가능하게", "RAG 방식에 시맨틱 청킹", "각각 상황마다 청킹 방식을 다르게", "할루시네이션이 안 생기도록 임베딩"

## 배경

`socraticRead` 는 한 장 안에서만 문맥을 본다. openclaw 는 전에 본 것을 기억하고 답하기 전에 먼저 찾아본다(Active Memory).
하지만 openclaw 는 본 것을 그대로 기억해 잘못된 내용이 조용히 섞이는 문제가 보고됐다 (arXiv 2603.23064).
이 기능은 **읽은 것을 기억해 다음 읽기의 문맥으로 쓰되, 검증된 것만 기억하고 기억에서 온 주장도 코드로 대조**한다.

## 사용자 시나리오

### US1 — 전에 읽은 것과 이어서 이해한다 (P1)
사용자가 카드 명세서 화면을 읽힌 뒤, 며칠 뒤 "연체 안내" 화면을 읽힌다.
에이전트는 두 번째 화면을 읽을 때 첫 번째 화면의 "결제일은 매월 14일" 을 찾아와
"이 연체 안내는 14일 결제일과 이어진다" 고 연결한다. 그 연결 문장에는 기억 조각 인용이 붙는다.

- 수락 조건 1: 기억에서 가져온 근거는 `[M3]` 처럼 표시되고, 인용 문장이 그 기억 조각에 글자 그대로 있다.
- 수락 조건 2: 관련 기억이 없으면 연결 질문은 "기억에 없음" 으로 남고, 지어낸 연결이 나오지 않는다.

### US2 — 글 종류에 맞게 잘라 저장한다 (P1)
긴 글은 의미가 바뀌는 곳에서, 제목이 있는 문서는 제목 단위로, 화면 캡처는 가까운 줄끼리,
표는 행 단위(머리글 포함)로, 대화는 발화 단위로, 코드는 함수 단위로, 짧은 글은 통째로 자른다.

- 수락 조건: 같은 입력은 항상 같은 조각으로 잘린다 (결정론). 조각마다 어떤 방식으로 잘렸는지(`kind`)와 원문 위치가 남는다.

### US3 — 검증된 것만 기억한다 (P1)
`socraticRead` 가 끝나면 원문 조각과 검증된 문답만 기억에 들어간다.

- 수락 조건: 반박된 답(refuted) · 버려진 요약 문장(dropped) · 근거 없는 추론은 기억에 없다.
- 수락 조건: 모든 기억 조각은 출처(문서 ID · 줄 번호 · 읽은 시각 · OCR 엔진과 신뢰도)를 가진다.

### US4 — 찾지 못하면 찾지 못했다고 한다 (P2)
관련 없는 질문으로 기억을 검색하면 빈 결과가 나온다.

- 수락 조건: 무관한 질문에 기억을 억지로 붙이지 않는다 (아래 SC-003).

## 기능 요구사항

- **FR-001** 입력의 종류를 자동 판별한다: `markdown` · `table` · `dialogue` · `code` · `screen`(OCR 좌표 있음) · `prose` · `short`.
- **FR-002** 종류별 청킹 전략을 적용한다. `prose` 는 시맨틱 청킹(인접 문장 임베딩 거리의 급변점에서 자름)을 쓰고, 최소·최대 길이를 지킨다.
- **FR-003** 임베딩은 로컬 모델(`multilingual-e5-small`, 384차원)로 한다. 키·네트워크 없이 동작한다 (최초 1회 모델 다운로드 제외).
- **FR-004** 검색은 **하이브리드**다: 임베딩 유사도 + 글자 겹침(n-gram) 점수. 임베딩만 쓰면 무관한 문장도 0.77 이 나와 오검색이 생긴다(실측).
- **FR-005** 검색 결과는 **절대 문턱 + 1등과의 차이(margin)** 를 모두 넘어야 돌려준다. 못 넘으면 빈 결과(= 기억에 없음).
- **FR-006** `socraticRead` 는 관련 기억을 `M1..Mk` 로 번호 매겨 프롬프트에 넣고, 기억 인용도 원문 인용과 같은 검증기로 대조한다.
- **FR-007** 질문 유형에 `connection`(전에 읽은 것과의 연결·모순)을 추가한다. 이 유형의 답은 기억 인용(M)과 원문 인용(L)을 모두 가져야 검증을 통과한다.
- **FR-008** 저장 대상: 원문 조각(`source`) · 검증된 문답(`fact`, 인용 포함). 그 외는 저장하지 않는다.
- **FR-009** 같은 내용(정규화 후 동일)은 중복 저장하지 않는다.
- **FR-010** 임베딩 모델을 쓸 수 없으면 글자 겹침 검색만으로 동작하고 결과에 이유를 남긴다.

## 성공 기준 (측정 가능)

- **SC-001** 청킹 결정론: 같은 입력 100회 → 100회 같은 조각. (테스트)
- **SC-002** 검색 정확도: 정답을 아는 질의 세트에서 정답 조각이 1등으로 나오는 비율(Top-1) 을 잰다. 목표 ≥ 90%.
- **SC-003** 거절 정확도: 기억과 무관한 질의 세트에서 빈 결과를 돌려주는 비율. 목표 ≥ 95%. (할루시네이션의 입구를 막는 수치)
- **SC-004** 기억 오염 0: 반박·버려진 내용이 저장되는 경우 0건. (테스트)
- **SC-005** 기억 인용 검증: 기억 조각에 없는 인용은 100% 반박. (테스트)
- 문턱·가중치는 질의 세트의 절반으로 고르고 나머지 절반으로 시험한다 (원칙 IV).

## 측정 결과 (2026-09-23 · `node server/memory/eval.js` · 문서 8 · 질의 48 · 절반 튜닝 / 절반 시험)

| 방식 | Top-1 (관련) | 무관 거절 | 비고 |
|---|---|---|---|
| 임베딩 유사도 ≥ 0.7 (흔한 기본값) | 100% | **0%** | 무관한 질의에도 전부 기억을 붙인다 — 할루시네이션 입구 |
| 임베딩 + 글자 겹침 + 문턱 (e5-small) | 58.3% | 83.3% | 관련/무관 코사인 분포가 겹친다 (관련 0.79~0.91, 무관 0.70~0.84) |
| 임베딩 + 문턱 (e5-base) | 83% | 83% | 전체 데이터 최선 조합 — 모델을 키워도 해결 안 됨 |
| **임베딩 후보 20 → 리랭커 (bge-reranker-v2-m3)** | **91.7%** | **100%** | 채택. 문턱 minRerank −7 |

- SC-002 (Top-1 ≥ 90%) **충족 91.7%**, SC-003 (거절 ≥ 95%) **충족 100%** — 시험 절반 기준.
- 남은 실패: "돈이 모자라면 어떻게 돼?" → 원문 "잔액이 부족하면" (표현이 크게 다른 질의).
- 함정 질의(주제는 같지만 답이 기억에 없음)는 검색이 그 문서를 찾아오는 것이 맞다. 답이 없다는 판단은 인용 검증(원칙 I)이 한다 — 실제 LLM 으로는 미측정.
- 비용: 리랭커 ~570MB, 최초 로딩 ~60초, 후보 8개 채점 0.26초.
