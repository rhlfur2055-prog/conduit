# 명세: 목표 + 하트비트 — 스스로 일을 시작하는 에이전트

- 기능 브랜치: `feat/agent-loop`
- 상태: 구현 완료 (2026-09-23)
- 입력 요청: "스스로 일을 시작 (목표·하트비트) 이제 해보자"
- 원칙: [constitution](../../.specify/memory/constitution.md)

## 배경

자동화 끝까지 테스트(server/automation.eval.js)에서 13단계 중 "스스로 일을 시작" 이 미구현이었다.
지금은 웹훅·크론·수동으로만 시작한다 — 크론은 **정해진 워크플로**를 깨울 뿐, 무엇을 할지 스스로 정하지 않는다.
openclaw 는 하트비트가 에이전트를 깨워 스스로 판단하지만, 백그라운드 판단이 검증 없이 기억을 오염시키는 문제가 보고됐다 (arXiv 2603.23064).

## 핵심 설계

**LLM 은 "무엇을 할지 제안" 만 한다. 실행은 코드가 검증한 뒤에만 한다.** (원칙 I)

```
하트비트(주기) → 상황 모으기: 목표 G · 새로 들어온 것 I · 최근 실행 E · 기억 M · 대기 중 승인 A
            → LLM: 목표별 제안 {goal, action: run|wait|ask, workflow, input, reason, evidence:[G1,I2,M1], confidence}
            → 코드 검증: 허용된 워크플로인가 · 근거 ID 가 실제로 있나 · 입력이 감지된 것인가 · 쿨다운 · 하루 상한
            → 통과 + 확신 높음 + 부작용 없음 → 실행 / 확신 낮음·부작용 있음 → 사람 승인 / 실패 → 기록만
            → 하트비트 기록(결정·검증·결과) → 다음 하트비트의 "최근 결정" 으로 들어간다
```

## 사용자 시나리오

### US1 — 폴더에 넣으면 알아서 읽는다 (P1)
목표 "받은편지함 폴더에 새 화면이 오면 읽고 기억해 둔다" 를 등록한다. 사용자가 `inbox/` 에 화면 캡처를 넣는다.
다음 하트비트에서 에이전트가 새 파일을 보고 "화면 읽기" 워크플로를 그 파일로 실행한다. 사람은 아무것도 누르지 않는다.
- 수락: 새 파일마다 한 번만 실행된다 (같은 파일을 두 번 읽지 않는다).

### US2 — 할 일이 없으면 아무것도 안 한다 (P1)
새 입력이 없고 목표 주기가 안 됐으면 `wait`. 하트비트가 돌아도 워크플로가 실행되지 않는다.

### US3 — 제안이 틀리면 막는다 (P1)
허용 안 된 워크플로 · 존재하지 않는 근거 ID · 감지되지 않은 파일 경로를 입력으로 넣은 제안은 실행하지 않고 기록만 한다.

### US4 — 애매하면 사람에게 묻는다 (P2)
확신도가 문턱 미만이거나, 목표에 "실행 전 승인" 이 켜져 있거나, 워크플로가 부작용(외부 발행)이 있으면 승인 요청을 보낸다.

### US5 — 키가 없어도 멈추지 않는다 (P2, 원칙 V)
LLM 을 못 쓰면 규칙 모드: 목표에 허용된 워크플로가 하나이고 새 입력이 있으면 그 입력으로 실행한다. 판단이 필요한 경우는 건너뛰고 이유를 남긴다.

## 기능 요구사항

- **FR-001** 목표 저장소: `{ id, text, workflows:[허용 ID], inbox?:폴더, cadenceMin, requireApproval, active }` + REST `/api/goals`
- **FR-002** 감지기: 목표의 `inbox` 폴더에서 아직 처리하지 않은 이미지·텍스트 파일 (처리 기록으로 중복 방지)
- **FR-003** 하트비트: `CONDUIT_HEARTBEAT` (크론식, 기본 꺼짐) 또는 `POST /api/heartbeat` 로 한 번 돌리기
- **FR-004** 제안 검증 (코드): 목표 존재·활성 · 워크플로가 그 목표의 허용 목록에 있음 · 근거 ID 가 이번 상황에 실제로 있음 ·
  입력의 파일 경로는 이번에 감지된 것만 · 목표별 쿨다운 · 하루 실행 상한
- **FR-005** 실행 경로: 통과 + 확신도 ≥ 문턱 + 승인 불필요 → `runtime.execute(trigger:'agent')`. 아니면 승인 요청 또는 기록만
- **FR-006** 하트비트 기록 저장 (결정 · 거부 이유 · 실행 ID · 결과) — 다음 하트비트에 "최근 결정" 으로 들어간다
- **FR-007** 기억은 이 경로로 쓰지 않는다. 기억은 워크플로(소크라테스식 읽기) 안에서 검증된 것만 들어간다 (원칙 III)

## 성공 기준

- **SC-001** 자동화 끝까지 테스트의 "스스로 일을 시작" 단계가 ✅ — 사람 손 없이 폴더에 넣은 화면이 읽히고 기억된다
- **SC-002** 잘못된 제안(허용 밖 워크플로 · 가짜 근거 · 감지 안 된 경로) 실행 0건 (테스트)
- **SC-003** 같은 입력 중복 실행 0건 · 할 일 없을 때 실행 0건 (테스트)
- **SC-004** 키 없이 규칙 모드로 US1 이 동작 (테스트)

## 측정 결과 (2026-09-23)

- **SC-001 충족** — `node server/automation.eval.js`: 두 번째 화면을 웹훅 없이 받은편지함 폴더에 넣기만 했더니
  하트비트가 스스로 읽기 워크플로를 시작 → OCR → 이해·검증 → 기억 연결 → 숨은 지시 차단 → 승인 요청까지 이어졌다.
  자동화 끝까지 테스트 14단계 중 자동 12 · 사람 1(승인 버튼) · 미구현 1(결과 답장) · 실패 0.
- **SC-002 · SC-003 · SC-004 충족** — `tests/server/heartbeat.test.js` 12개: 허용 밖 워크플로 · 가짜 근거 · 감지 안 된 경로 ·
  남의 입력 · 없는 목표 · 파일 이름으로 서버 파일 읽기 시도 → 실행 0건. 같은 입력 중복 0건. 키 없이 규칙 모드로 동작.
- LLM 제안 품질(어떤 상황에서 run/wait/ask 를 잘 고르는가)은 실제 키가 없어 미측정.
