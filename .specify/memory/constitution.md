# Conduit 원칙 (Constitution)

모든 명세·계획·구현은 이 원칙을 먼저 통과해야 한다. 계획(plan.md)의 "원칙 점검" 표에서 항목마다 확인한다.

## I. 검증은 모델 밖에서 한다

LLM 이 만든 주장은 코드로 대조할 수 있는 근거(원문 인용·줄 번호·기억 조각 ID)를 달아야 한다.
대조는 결정론적 코드가 한다. 모델이 자기 답을 스스로 검증하게 하지 않는다.

## II. 모르면 모른다고 한다

근거가 문턱을 넘지 못하면 답을 지어내지 않고 "원문/기억에 없음"을 돌려준다.
빈칸을 추측으로 채우는 것보다 비워 두는 것이 옳은 동작이다.

## III. 검증되지 않은 것은 기억하지 않는다

장기 기억에는 원문 자체(출처 포함)와 검증을 통과한 사실만 들어간다.
반박된 답, 근거 없는 요약 문장, 추측은 저장하지 않는다. 한 번 들어간 오류는 이후 모든 답을 오염시킨다.

## IV. 숫자는 재서 말한다

성능·정확도 주장은 정답을 아는 데이터로 잰 숫자로만 한다. 가중치·문턱을 고른 데이터와
시험하는 데이터를 나눈다 (예: 글꼴 하나를 빼고 검증). 측정하지 않은 것은 "미측정"이라고 쓴다.

## V. 없어도 멈추지 않는다

키·외부 서버·모델이 없으면 기능은 시뮬레이션이나 더 약한 경로로 떨어지고, 이유를 결과에 남긴다.
단, 사용자가 특정 경로를 명시했는데 쓸 수 없으면 조용히 바꾸지 않고 오류를 낸다.

## VI. 테스트가 먼저 고정한다

결정론적인 부분(검증기·청킹·검색 규칙·상태 전이)은 가짜 모델로 테스트를 먼저 쓴다.
모델 품질은 테스트가 아니라 평가(정답셋 대비 %)로 따로 잰다.
