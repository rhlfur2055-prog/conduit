# 명세: 텔레그램 양방향 — 휴대폰 ↔ PC

- 기능 브랜치: `feat/agent-loop`
- 상태: 초안 (2026-09-23)
- 입력 요청: "텔레그램 노드 연결, 컴퓨터에서 휴대폰 연결 — 두 가지 방향으로 두자", "사용자가 선택할 수 있도록"
- 원칙: [constitution](../../.specify/memory/constitution.md)

## 두 방향

| 방향 | 무엇 | 지금 |
|---|---|---|
| **받기 — 휴대폰 → PC** | 텔레그램으로 사진·글을 보내면 PC 의 받은편지함에 들어가고, 하트비트가 바로 읽는다 | 없음 (폴더에 직접 넣어야 함) |
| **보내기 — PC → 휴대폰** | 읽은 결과(이해 요약 · 원문에 없던 것 · 승인 대기 여부)를 보낸 채팅으로 답장. 워크플로의 텔레그램 노드로도 보낸다 | 승인 버튼만 있음 |

## 사용자가 고른다

모드: **둘 다 · 받기만 · 보내기만 · 끄기** (기본: 끄기 — 켜기 전에는 아무것도 주고받지 않는다)

- conduit 화면: 설정 → 텔레그램 (모드 · 받은 것을 넣을 목표 · 연결 상태)
- 텔레그램: `/mode` → 버튼 4개로 바꾼다. `/status` → 현재 모드와 최근 하트비트

## 사용자 시나리오

### US1 — 휴대폰으로 찍어 보내면 읽고 답한다 (P1, 둘 다)
명세서를 휴대폰으로 찍어 봇에게 보낸다 → PC 받은편지함에 저장 → 하트비트가 바로 읽기 워크플로 실행 →
"이 문서는 … (근거 L2) · 원문에 없는 것: 연회비" 가 같은 채팅으로 답장된다.

### US2 — 받기만 (P2)
사진은 받아서 읽고 기억하지만 휴대폰으로 답장은 하지 않는다 (조용히 쌓기).

### US3 — 보내기만 (P2)
휴대폰에서 보내는 사진은 받지 않는다. PC 에서 읽은 결과·승인 요청만 휴대폰으로 온다.

## 요구사항

- **FR-001** 모드 저장 (`settings.json` 의 telegram.mode) + REST `GET/PUT /api/settings/telegram` + 텔레그램 `/mode` `/status`
- **FR-002** 받기: 허용 채팅(TELEGRAM_CHAT_ID)에서 온 사진 · 이미지 문서 · 글만. 10MB 상한. 파일은 목표의 받은편지함에
  `tg_<채팅>_<메시지>.<확장자>` 로, 보낸 곳은 옆의 `.meta.json` 에 저장한다. 받으면 하트비트를 바로 한 번 돌린다
- **FR-003** 하트비트: 입력에 `.meta.json` 이 있으면 **코드가** 입력에 `replyTo` 를 붙인다 (LLM 이 정하지 않는다 — 다른 채팅으로 보내게 할 수 없다)
- **FR-004** 보내기: replyTo 가 있는 실행이 끝나면 결과를 그 채팅으로 답장. 내용은 코드가 만든다
  (검증된 요약 문장 · 원문에 없던 질문 · 승인 대기 여부). 허용 채팅이 아니면 보내지 않는다
- **FR-005** 모드가 막으면 아무 동작도 하지 않고 이유를 기록한다 (받기 끔 → 사진에 "지금은 받지 않습니다" 한 번 안내)

## 성공 기준

- **SC-001** 가짜 텔레그램 API 로: 사진 보냄 → 저장 → 하트비트 실행 → 같은 채팅으로 답장, 사람 손 0 (테스트)
- **SC-002** 모드 4가지 각각 받기·보내기가 정확히 켜지고 꺼진다 (테스트)
- **SC-003** 허용 안 된 채팅의 사진은 저장 0건 · 답장 0건 (테스트)
- **SC-004** 설정 화면에서 모드를 바꾸면 텔레그램 쪽 동작이 바로 바뀐다

## 범위 밖

- 음성·동영상
- 여러 사용자·그룹 권한 관리 (허용 채팅 목록으로만)
