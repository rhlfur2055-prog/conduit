# 명세: 개인 비서 — 골라서 쓰기 · 말로 시키기 · 휴대폰으로 받기

- 기능 브랜치: `feat/agent-loop`
- 상태: 구현 완료 (2026-09-23) — LLM 이 규칙 밖의 말을 얼마나 잘 옮기는지는 실제 키가 없어 미측정
- 입력 요청: "localhost:8787 을 실제 n8n 과 openclaw 처럼 자동화 기능으로", "개인비서화 · 골라서 쓰기 · 말로 시키기"
- 원칙: [constitution](../../.specify/memory/constitution.md)

## 세 가지

| | 무엇 | 비슷한 것 |
|---|---|---|
| **골라서 쓰기** | 비서 템플릿을 고르고 빈칸 몇 개(시간·주소·문구)만 채우면 자동화가 켜진다 | n8n 템플릿 |
| **말로 시키기** | 텔레그램·화면 채팅에 "매일 8시 30분에 약 먹으라고 알려줘" → 비서가 알아듣고 확인을 받은 뒤 켠다 | openclaw 채팅 |
| **휴대폰으로 받기** | 템플릿 결과는 텔레그램으로 온다. 자동화가 실패하면 알려 준다 | openclaw 알림 |

## 템플릿 (개인 비서용, 처음 5개)

| ID | 이름 | 채울 것 | 흐름 |
|---|---|---|---|
| `read-and-reply` | 사진·글 읽고 답하기 | 없음 | 받은편지함/텔레그램 → 소크라테스식 읽기 → 답장 (005) |
| `reminder` | 할 일 알림 | 시각 · 요일(매일·평일·주말) · 문구 | 예약 → 텔레그램 |
| `morning-brief` | 아침 브리핑 | 시각 | 예약 → 오늘의 인기 검색어 3개 → 요약 → 텔레그램 |
| `page-watch` | 웹페이지 바뀌면 알림 | 주소 · 확인 간격 | 예약 → 페이지 받기 → 변경 감지 → 바뀌면 텔레그램 |
| `memory-digest` | 이번 주 읽은 것 정리 | 요일·시각 | 예약 → 기억에서 이번 주 사실 → 텔레그램 (검증된 것만) |

## 말로 시키기 — 설계

**비서는 제안하고, 사람이 [만들기] 를 눌러야 켜진다. 실행은 코드가 검증한 뒤에만.** (원칙 I)

1. **규칙으로 먼저 알아듣는다** (키 없이도 동작 · 결정론 · 테스트 가능):
   알림("매일 8시 30분에 … 알려줘") · 페이지 감시("https://… 바뀌면 알려줘") · 실행("○○ 돌려줘") ·
   기억("전에 읽은 결제일 뭐였지?") · 목록("템플릿 보여줘", "자동화 목록") · 상태("요즘 뭐 했어?") · 도움말
2. 규칙으로 못 알아들으면 **LLM 이 정해진 동작 중 하나로 옮긴다** (template · run · recall · list · status · unknown).
   코드가 검증: 템플릿이 있나 · 채울 값이 형식에 맞나(시각 00:00~23:59, 주소 http(s)) · 워크플로가 있나
3. 자동화를 **새로 만들거나** 밖으로 내보내는 워크플로를 **실행**하는 것은 확인 버튼 [만들기]/[취소] 를 거친다
4. 기억 질문은 LLM 이 답을 쓰지 않는다 — **기억 조각 원문을 출처와 함께 그대로** 보여 준다 (지어낼 자리가 없다)

## 텔레그램에서의 구분

- 사진 · 이미지 · 글 파일 → 읽기 (005 그대로)
- 짧은 글 → **말로 시키기** / 긴 글(200자 이상) 또는 "읽어줘 …" → 읽기

## 요구사항

- **FR-001** 스케줄 트리거에 "직접 지정"(크론식) 추가 — 템플릿의 시각·요일을 담는다
- **FR-002** 변경 감지 노드(`changeDetect`) — 키별로 지난 값의 해시를 저장, 바뀌면 changed 포트
- **FR-003** 템플릿 목록 · 만들기 API (`/api/templates`), 값 검증 후 워크플로 저장 + 예약 등록
- **FR-004** 비서 API (`/api/assistant`) + 확인 (`/api/assistant/confirm/:id`) · 텔레그램 짧은 글 연결
- **FR-005** 자동화 실패 알림 (설정: 실패만 · 모두 · 끄기, 기본 실패만) — 보내기 모드일 때만
- **FR-006** 화면: 쉬운 시작에 [골라서 쓰기] 카드 갤러리 · [말로 시키기] 채팅창

## 성공 기준

- **SC-001** 템플릿 5개가 각각 올바른 워크플로·예약(크론식)을 만든다 (테스트)
- **SC-002** 대표 문장 20개를 규칙으로 올바른 동작·값으로 알아듣는다 (테스트 · 비율 측정)
- **SC-003** 확인 없이 자동화가 만들어지거나 부작용 워크플로가 실행되는 경우 0 (테스트)
- **SC-004** 기억 질문의 답은 기억 조각 원문뿐 — 없는 내용이 답에 나오는 경우 0 (테스트)
- **SC-005** 로컬 끝까지 점검에 "텔레그램으로 '매일 8시 30분에 약 먹으라고 알려줘' → [만들기] → 예약 생성" 추가

## 측정 결과 (2026-09-23)

- **SC-001** 템플릿 5개 → 올바른 노드·크론식 (`tests/server/assistant.test.js`) ✅
- **SC-002** 대표 문장 20/20 을 규칙으로 올바른 동작·값으로 알아들음 ✅ — 처음엔 19/20 ("핫이슈 쇼츠 실행해줘" 를 브리핑으로 오인 → 브리핑 규칙을 "보내·알려" 가 있을 때로 좁힘)
- **SC-003** [만들기] 전 자동화 생성 0 · 부작용 워크플로는 실행 전 확인 · LLM 이 준 값도 같은 검증 ✅
- **SC-004** 기억 질문 답은 기억 원문 + 출처·날짜만 ✅ — 처음엔 군말("전에 읽은 … 뭐였지") 때문에 기억을 못 찾음 → 찾을 말만 남기는 정리 추가 (단어 끝 글자를 조사로 오인해 자르던 것도 고침)
- **SC-005** 로컬 끝까지 점검 33/33 — 휴대폰 "매일 8시 30분에 약 먹으라고 알려줘" → [만들기] → 크론 `30 8 * * *` 자동화 켜짐 ✅
